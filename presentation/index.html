Three quality gates

① Content audit — /quality-audit: five-dimension 12-Iron-Rule check (header quality / template residue / SNN error specificity / progressive complexity / VHDL body quality); violations must be fixed.
② External verification — /ghdl-verify: full compile with the public tool GHDL; four-way failure classification (file bug / metadata misclassification / harness defect / tool gap); fix to 0 failures; tool gaps must be explicitly allowlisted with a reason.
③ Documentation consistency — /doc-sync: unified sync_all.py sync + verify-only cross-check (§9 ↔ filesystem ↔ Tracker ↔ coverage ↔ appendix ↔ mindmap ↔ GHDL gate); 0 issues means done.

04Methodology Accumulated

5 Iron Rules (non-negotiable)

  • Sync is mandatory: after any cases_src change /doc-sync is required and the output must be 0 issues — never skipped
  • Batch = track + complete: read PRODUCTION_TRACKER before batch work, sync every ~5 productions
  • Quality is verified: must pass /quality-audit before reporting "done"
  • Methodology lives in skills: CLAUDE.md only orchestrates; all 12 Iron Rules etc. are pushed down into skills
  • External verification is the quality gate: GHDL 0 non-allowlist failures; gaps must be explicitly allowlisted with a reason

12 Iron Rules (content quality)

  • 9 content rules: one file one test point / the body exercises the production's real syntax / meaningful entity names / multi-variant ports / zero dead code / SNN errors must come from a specific BNF token / SNN parseable up to the error point / SYN_001 minimal → SYN_00N progressively thorough / realistic hardware style
  • 3 traceability rules: Test Focus format [dimension]:[mechanism] / reports write HOW not WHAT / report ↔ header ↔ code three-layer consistency

Four-way failure classification (external verification)

verify gate philosophy (anti-drift)

  • Single source of truth: the filesystem is the only truth, docs are fully generated — real case: after the three-way stat contradiction, no more patching
  • Full regeneration beats patching: patch-style updates fix one place and miss two — the root cause of silent staleness
  • Blind-spot sealing: every "unchecked thing" discovered gets added to verify — blind-spot sealing now also covers factual claims (numbers/paths/architecture counts), not just missing checks — already sealed: the script set (GHDL drift), the debt-chapter structure, the claim domain (Facts Authority + Claim Registry, verify 7k)
  • Done = verify 0 issues: not by memory, enforced by script; reverse tests proved the gate really blocks (a fake failure row → GHDL GATE alarm)
